# web_scraping — корпус русскоязычных новостей для бизнес-инсайтов

Обязательный парсер новостей из ТЗ.
Приоритет: экономические, деловые, отраслевые, регуляторные и бухгалтерско-правовые источники (tier 1),
затем политика, технологии и наука из общих СМИ и научных изданий (tier 2). Спорт, культуру и шоу-бизнес отсекаем.

## Пайплайн (`python -X utf8`, из этой папки: `cd stage1_news_pool/web_scraping`)

| Стадия | Скрипт | Выход в `data/news/` |
|---|---|---|
| 1. URL за N дней: sitemap + RSS + дневные архивы | `discover.py [--days 31] [--only src ...]` | `index.jsonl` — url, source, tier, topic, date, title, summary, rss_category |
| 2. Загрузка + извлечение текста (trafilatura), можно дозапускать | `fetch.py [--tier 1] [--per-source N]` | `articles.jsonl` |
| 3. Очистка и сборка | `build.py [--days 31]` | `news.parquet`, `news.jsonl` |

- `--only` обновляет указанные источники в существующем индексе, остальные сохраняются.
- Fetch: 3 запроса на хост, сначала tier 1; извлечение текста идёт в процессах, потому что lxml в потоках падает на Windows.
- Build:
  - охват задаёт индекс;
  - дата берётся со страницы;
  - отсекаются тексты короче 200 символов и тексты без кириллицы;
  - отсекается off-topic по URL и рубрике, у tier 2 ещё криминал и происшествия;
  - точные дубли текста схлопываются в пользу tier 1.

Поля `news.parquet`: `id, tier, topic, source, date, url, title, summary, text, rubric, author, tags, published, published_page, date_src`.
`topic` — тема источника по умолчанию (`economy`, `finance`, `markets`, `monetary`, `legal`, `accounting`, `oil_gas`, `energy`,
`agro`, `retail`, `construction`, `transport`, `auto`, `pharma`, `tech`, `telecom`, `science`, …). Для общих СМИ поле пустое,
тогда тему даёт `rubric` и дальнейшая классификация в основном пайплайне.

## Состояние на 2026-10-20
- Индекс за 31 день (17.09–19.10): **141 302 URL** — tier 1: 55 316, tier 2: 85 986.
- Крупнейшие источники tier 1: Коммерсант 19k, Прайм 7.4k, Интерфакс 5k, Ведомости 3.9k, РБК 3.3k, BFM 2.9k.
- Загрузка текстов идёт фоном: сначала tier 1, затем tier 2. После неё нужно запустить `build.py`.

Пересборка теперь публикуется через `common.news_corpus.publish_news`: сохраняется снимок старого корпуса,
новые ID вычисляются из нормализованных URL, события готовятся до замены основного файла. В
`data/news/rebuild_report.json` записываются переходы ID и состояние ссылок сохранённых инсайтов.
Эмбеддинги создаются при первом обращении для конкретного fingerprint корпуса; старый файл векторов не подмешивается.
Сохранённые результаты без версии источников не сопоставляются по одному числовому ID.

## Расширение
1. **Глубина RSS-only источников.**
   - Регулярно опрашивать RSS (cron раз в 2–4 ч): месяц накопится сам.
   - Для прошлого: GDELT DOC API (`sourcelang:russian`, фильтр по доменам из `sources.py`) и Common Crawl CC-NEWS.
2. **Интерфакс глубже:** sitemap отдаёт около 26 дней. Добрать через архив `interfax.ru/news/{y}/{m}/{d}`.
3. **Регуляторы:**
   - ЦБ: пресс-релизы, решения СД, обзоры;
   - Минфин, Минэк, government.ru: парсинг HTML-лент;
   - regulation.gov.ru: проекты НПА для главбуха и CFO.
4. **Компании:** раскрытие e-disclosure и Интерфакс-ЦРКИ, пресс-релизы эмитентов Мосбиржи. Это прямые события по контрагентам.
5. **Telegram-каналы** через веб-превью `t.me/s/<канал>`: деловые (РБК, Интерфакс, Frank, MarketTwits), отраслевые, ЦБ.
6. **Качество:**
   - кластеризация почти-дубликатов между СМИ (MinHash по шинглам) → «событие ≠ новость»;
   - очистка суффиксов сайта в заголовках;
   - классификация тем и значимости через Gemma, один раз на новость (см. план бюджета в [case-notes.md](../case-notes.md)).
