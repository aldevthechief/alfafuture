# Автоматическое пополнение корпуса

Запускается отдельным процессом из корня проекта; `pipeline.py` и агентские циклы его не запускают.
Один проход: обнаружение URL → загрузка → очистка во временной папке → объединение с текущим корпусом → публикация.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m stage1_news_pool.updater --once --only cbr --limit 20
.\.venv\Scripts\python.exe -X utf8 -m stage1_news_pool.updater --interval 900 --days 7
```

Вторую команду держать в отдельном терминале параллельно работающему приложению. Ctrl+C останавливает процесс.
`--only` ограничивает источники из `web_scraping/sources.py`, `--limit` — загрузки за проход,
`--timeout` — максимальное время каждого этапа (по умолчанию 1800 секунд), `--folder` — каталог корпуса.
Пайплайн использует каталог `ALFA_DATA/news`; при нестандартном `--folder` согласуйте его с `ALFA_DATA`.

Обновление сохраняет прежние статьи, включая историю старше `--days`: окно ограничивает обнаружение новых URL.
URL нормализуются; повторная загрузка обновляет статью, повторный одинаковый проход не перепубликует корпус.
Успешно собранная часть источников может быть опубликована при недоступности остальных.
Пустой результат не очищает корпус. Ошибка этапа оставляет рабочий `news.parquet` нетронутым;
неудачный периодический проход повторяется через заданный интервал.
Статус последнего прохода: `data/news/updater_status.json`, подробности сборщика — в терминале.

Блокировка ОС `updater.lock` не допускает двух одновременно работающих обновляторов и снимается при завершении процесса.
Не запускайте старый `build.py` в тот же каталог параллельно обновлятору: его отдельный CLI эту блокировку не использует.
Публикация использует существующие архивы версий и атомарную замену parquet. Индексы и события сверяют отпечаток корпуса.
Следующий запрос пайплайна видит новые новости автоматически. Текущий анализ закрепляет снимок корпуса до завершения, включая вложенный поиск. Новые запросы получают опубликованную версию. Результаты сохраняют ссылки на свой исходный снимок.

Обновлятор проверяет известные URL условными HTTP-запросами с ETag/Last-Modified. Ответ 304 пропускает загрузку тела и обработку. Если сервер не поддерживает условные запросы, сравнивается хеш тела страницы: неизменившийся HTML не парсится и не очищается. Изменение HTML требует разбора, даже если затем выяснится, что текст статьи прежний. `--limit` ограничивает число проверок за цикл; ранее проверенные URL ротируются, чтобы изменения старых публикаций не оставались незамеченными. LLM и первоначальный агентский цикл обновлятору не требуются.

Гибридный поиск, cross-encoder и инкрементальное извлечение фактов: [инструкция](../docs/HYBRID_NEWS_SEARCH.md).


Инкрементальные кеши: `collector.sqlite3` хранит HTTP-валидаторы, хеш страницы и отпечаток опубликованного текста; `vectors.sqlite3` — векторы по модели и содержимому статьи. Оба файла исключены из Git. После первой обработки повторный запуск переиспользует готовые данные; удаление кеша безопасно, но потребует повторного вычисления.

При смене модели или изменении текста FRIDA вычисляет только отсутствующие векторы; итоговый массив собирается в порядке ID текущего снимка. Готовый старый NPZ также переносится в кеш отдельных векторов. Лексический TF-IDF индекс и события пересобираются для нового снимка: IDF зависит от состава всего корпуса, поэтому его обновление затрагивает и прежние документы. Повторного извлечения текста и LLM-фактов для неизменённых статей нет.

Публикация использует атомарный `news.parquet` и архивы версий. Читатели закрепляют DataFrame, лексический индекс и проверенные события за версией анализа; векторы также сверяются с ней. Файлы JSONL/отчёты служебные, вход пайплайна — parquet. Сбой до публикации не позволяет кешу загрузчика пропустить неподтверждённое обновление. После перезапуска неуспешные статьи проверяются снова.
