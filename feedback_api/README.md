# Вопросы к инсайту и реакции, которые меняют следующий подбор

Пользователь ставит реакцию на готовый инсайт (👍 / 👎 / эмодзи / «полезно» / «не интересно» / «уже знаю» / «неверно»)
или задаёт вопрос. Ответ на вопрос строится только по материалам этого инсайта и явным поискам «только чтение»;
реакции сохраняются и при следующем запуске `pipeline.py --user-id <id>` меняют выбор новостей для этого пользователя.
Основа — наработка ветки `maxon_dialogue` (aldev), перенесённая на контракт инсайта v2.

## Запуск

```bash
pip install -r requirements.txt
python -m uvicorn feedback_api.app:app --host 127.0.0.1 --port 8001        # Swagger: http://127.0.0.1:8001/docs
python -X utf8 -m feedback_api.importer data/insights/U_42222_cfo.json --user-id demo   # зарегистрировать готовые инсайты
python -X utf8 pipeline.py U_42222 --role cfo --user-id demo               # подбор с учётом реакций demo
```

## API (заголовок `X-User-ID` в каждом `/v1` запросе)

| Метод | Что делает |
|---|---|
| `POST /v1/insights/import` | зарегистрировать готовые инсайты из результата пайплайна; снимок доказательств собирается кодом |
| `GET /v1/companies/{id}/insights?role=` | инсайты пользователя по компании и роли |
| `POST /v1/insights/{id}/feedback` | реакция или комментарий: `{kind, emoji?, comment?, scope?, request_id}` |
| `POST /v1/insights/{id}/ask` | вопрос: `{question, request_id, remember?}` → ответ со ссылками `news:` / `fact:` / `bank:` / `lookup:` |
| `GET /v1/insights/{id}/feedback`, `/reactions` | история обсуждения, счётчики реакций |
| `DELETE /v1/feedback/{id}` | удалить свою реакцию или сообщение (и её влияние на подбор) |
| `GET /v1/companies/{id}/personalization?role=` | что применит следующий запуск пайплайна |

`POST /v1/insights/{id}/ask` и потоковый `/ask/stream` принимают `selected_text` (до 2000 символов)
и `selected_source`: `insight` по умолчанию или `answer` для фрагмента готового ответа агента.
Цитата и её происхождение сохраняются в истории и учитываются при проверке повторного `request_id`.
При `answer` модель получает указание перепроверить прежний ответ по материалам инсайта: цитата
не становится подтверждённым источником. Старые записи читаются как цитаты из инсайта;
SQLite дополняется колонкой автоматически без потери истории.

## Отдельный чат компании

«Чат с банком» использует `FeedbackAnalyzer.complete`, тот же `DiscussionLoop`, модель и SSE-транспорт,
но собственный системный промпт и таблицы `company_chats` / `company_chat_messages` в той же SQLite.
Ключ разговора — `(user_id, company_id, role)`; сообщения из обсуждений инсайтов не подмешиваются.

| Метод | Что делает |
|---|---|
| `POST /v1/company-chats` | `{company_id, role}` → создать или вернуть разговор; без LLM |
| `GET /v1/company-chats/{id}/messages?limit=50&before={message_id}` | последние сообщения в хронологическом порядке, `before` / `has_more` для загрузки предыдущих |
| `POST /v1/company-chats/{id}/ask/stream` | `{question, request_id, selected_text?}` → события `text`, `complete`, `error` |

Во всех запросах обязателен `X-User-ID`. Чужой ID разговора возвращает 404; в режиме `server` POST запрещён.
Контекст каждого нового вопроса — карточка, факты компании и явно сохранённые пользовательские уточнения.
Он сохраняется вместе с вопросом; повторный `request_id` использует прежний снимок и готовый ответ.
GET отдаёт только процитированные факты из снимка ответа, а не весь профиль. Изменение профиля не меняет старые ссылки.
Разговор сам по себе не изменяет персонализацию инсайтов. Инструменты привязаны к компании,
инструменты исходного события (`same_event_reports`, `follow_up_news`) отсутствуют.

## Redis-кеш ответов

При `ALFA_CACHE_REDIS_URL` включается отдельный кеш проверенных ответов
`alfa:feedback:answer:v1:<sha256>`. Docker Compose уже передаёт этот адрес сервису диалога.
`FEEDBACK_LLM_CACHE_TTL` задаёт срок хранения в секундах (по умолчанию `3600`, `0` отключает).
Без Redis файловый кеш диалога не создаётся; ошибки чтения/записи Redis не мешают получить новый ответ.

Ключ учитывает пользователя, компанию, роль, исходное событие, полный инсайт и снимок материалов,
вопрос/комментарий и scope, последние 8 сообщений с ответами, дату сообщения, модель с параметрами
и адресом прокси, промпты, схемы инструментов и лимит шагов. UUID запросов/сообщений и время внутри дня
не влияют на ключ; `user:*` в ответе преобразуются в ID сообщений текущего диалога.
Одинаковый вопрос после нового уточнения пользователя считается другим контекстом.

Если ответ использовал поиск, при чтении кеша повторяются те же инструменты только чтения:
изменились выданные материалы или поиск недоступен — запускается новый разбор. Кешируются только
успешные ответы с проверенными ссылками; ошибки, обрезанные ответы и ответы после ошибок инструментов
не записываются. Кеш не ускоряет первый разбор нового контекста и не объединяет похожие вопросы.

История, реакции и готовые ответы по-прежнему сохраняются в SQLite. Повтор того же `request_id`
возвращает сохранённую запись без Redis и LLM. Для отдельных одновременных запросов кеш
не гарантирует единственный вызов модели, если они оба пришли до сохранения ответа.

## Как реакция влияет на цикл агента

`common/personalization.py`, применяется в обоих движках `pipeline.py` (judge и loop):
1. «не интересно» и «уже знаю» → новость исключается из кандидатов **до** этапа 4: на неё не тратятся вызовы LLM.
2. 👍 / «полезно» и 👎 / «не интересно» меняют вес темы инсайта (канал этапа 3: `rate`, `fx`, `fuel`, `housing`, …):
   сглаженно, одна реакция — ×1.2 / ×0.83, итог в [0.6, 1.5]. Тема — из `insight.channel`, иначе из заголовка.
3. Новость, похожая по основам на понравившийся / непонравившийся инсайт, получает до +30% / −30%.
4. Приоритет этапа 4 умножается на итоговый коэффициент; коэффициент сохраняется в результате (`stage4.personalization_factor`).
5. Текстовые уточнения пользователя (`scope=future`) попадают в оценку релевантности отдельным блоком
   «не подтверждённые факты, со слов пользователя».

Эмодзи с однозначным смыслом (👍 ❤️ 🔥 💡 👏 / 👎 😴 🙄) считаются лайком / дизлайком, остальные сохраняются нейтрально.
Реакции по умолчанию `scope=future`, вопросы и комментарии — `scope=insight` (вопрос с `remember=true` — future).
Всё изолировано по `(user_id, company_id, role)`.

## Безопасность

- `X-User-ID` — идентификатор от доверенного бэкенда, не аутентификация банка. С `FEEDBACK_API_TOKEN` каждый `/v1` запрос
  требует `Authorization: Bearer <token>`; токен не должен попадать в браузер.
- Пользователь видит и меняет только свои инсайты и реакции (404 на чужие). Повтор с тем же `request_id` не дублирует запись,
  другое содержимое — 409.
- Ответ модели принимается, только если все `source_ids` есть в снимке инсайта, в реально выданных поисках или в сообщениях
  пользователя; иначе модель получает ошибку, а после бюджета шагов API отвечает 502 (вопрос сохранён). Инструменты только
  читают данные компании и события инсайта; до 4 обращений к данным, до 16 тыс. символов текста.
- Тексты пользователя и источников — данные, а не инструкции (промпт `prompts/analyze.md`); в логи не пишутся.
- База `data/feedback/feedback.sqlite3` — персональные данные, в `.gitignore`.
- Для прода не хватает: rate limiting, аутентификации через сессию банка, шифрования базы в покое.

## Живая проверка (23.10.2026, U_31505, роль cfo, GLM-5.3-Flash через прокси)

`NEWS_SEARCH_DENSE=0 NEWS_SEARCH_RERANK=0 pipeline.py U_31505 --role cfo --engine judge --source news --retrieval lexical
--candidates 6 --judge 2` → импорт → реакции → вопрос → тот же запуск с `--user-id demo-user`.

| Шаг | Результат | Стоимость |
|---|---|---|
| Первый подбор | 2 готовых инсайта: 2199 «Запрет экспорта дизеля продлён…», 4845 «Подорожавшее топливо требует больше оборотного капитала…» | ~4,4 ₽ |
| Импорт | снимок: 4 новости, 86 фактов компании | — |
| Реакции | «уже знали» на 2199, 👍 на 4845 → правила, без модели | — |
| Вопрос | «Насколько вырастет потребность в оборотке при +10% к дизелю и что сделать на неделе?» → за 10 с сценарный расчёт (+170–580 млн ₽/год по доле дизеля) с пометкой «вывод AI», ссылки на `fact:` и `news:`, три действия | ~0,9 ₽ |
| Повторный подбор | `1 news excluded, topics {'fuel': 1.2}`: 2199 не дошла до этапа 4; к судье ушли 4845 и новая топливная 6696 (оба ×1.32) | ~7 ₽ |

Во втором запуске готовых инсайтов 0: черновик по 4845 отклонила самопроверка писателя (блок пользовательского контекста
изменил промпт релевантности, кеш не сработал, модель написала другой текст), по 6696 судья не нашёл инсайта. Механика
подбора подтверждена; для демо брать `--judge 4` и больше, на двух новостях итог зависит от случайности модели.
Найдено и исправлено по ходу: в реальных инсайтах `insight.channel` пуст — тема теперь берётся из заголовка;
«Запрет экспорта дизеля» определялся как «зерно» — убрано общее слово «экспорт», добавлены формы «дизеля».
