# Чувствительность компании к рычагам (каналам влияния)

Новость и компания описываются в одних координатах — 21 рычаг `A1–H1` из `experiments/news_channels/channels.py`
(ставка, цены на сырьё, пошлины, погода, санкции, …). Ничего не берётся из новостного корпуса, поэтому работает
на любых новостях, в том числе на датасете жюри.

```
важность(новость, компания) = Σ по рычагам  сила_новости[рычаг] × чувствительность_компании[рычаг]
```

- **Сторона компании** — [`levers.py`](levers.py), поле `sensitivity` в `profiles.jsonl`: вес 0..1 и `reasons`
  (id внешних факторов и фактов) по каждому рычагу. Источники: внешние факторы профиля (каждый фактор ложится на рычаг
  по правилам на название, иначе по теме) и правила по данным компании — кредит/лизинг → D1 1.0, D2 0.8; факторинг → D4;
  гарантии → A3; ФТС → D3 0.8, A4 и E1 0.5 (направление неизвестно), недружественная страна → E1 0.9; иностранный
  собственник → C5 0.8; госсобственность → A3; штат → B4; крупный бизнес → D2. Базовый слабый уровень у всех: D1, C1 0.3.
- **Сторона новости** — должна приходить от ансамбля моделей Максона (`experiments/news_channels`, AUC 0.90 к GLM).
  Пока его оценок нет в репозитории, [`news_levers.py`](news_levers.py) даёт простую замену: словарь основ по рычагам
  + совпадение с товарами/сырьём отрасли компании. `match()` принимает любую матрицу [новости × 21].

## Замер на golden set этапа 3 (11 компаний, 33 новости, 21.10.2026)

| Ранжирование | топ-100 | топ-300 |
|---|---|---|
| лексическое расширение (`expansion/`) | 10/33 | 14/33 |
| рычаги × чувствительность (словарная сторона новости) | 3/33 | 9/33 |
| лексика + 0.3 × рычаги | 11/33 | 16/33 |
| RRF(лексика, рычаги) | 9/33 | 17/33 |

Рычаги сами по себе слабы: новостей «про ставку» или «про санкции» сотни, а рычаг не знает масштаба события
(то же у Максона: каналы без компании — AUC ≈ 0.6 к судье). Вместе с лексикой дают +2–3 новости в топ-300; на 33 новостях
это на грани шума. Ожидаем, что модельная сторона новости вместо словаря и учёт значимости события усилят этот сигнал.
Главная польза вектора — структурированная причина «почему это касается компании» для этапов 4–6.
