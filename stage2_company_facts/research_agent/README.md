# Агент исследования компании (LangGraph, GLM-5.3-Flash через LLM-прокси организаторов)

Агент дополняет `deterministic_facts/facts.py`. Факты скрипта даются ему как **известные** — их не нужно искать
или пересказывать. Главная цель агента — **неочевидные гипотезы** о бизнес-модели (сверх ОКВЭД и цифр карточки)
и их проверка с попыткой опровергнуть. Попутно он собирает **новые факты, которых строго нет в известном наборе**,
и возвращает их в `finish(new_facts, summary)`.

```bash
set LLM_API_KEY=...   (или common/llm/.env)
python -X utf8 stage2_company_facts/research_agent/agent.py U_44767 --max-steps 40   # -> data/companies/agent/U_44767.json
python -X utf8 stage2_company_facts/research_agent/test_agent.py                     # офлайн-тест графа на скриптованной модели
```
Первый живой прогон (U_106783, 13,47 ₽) упёрся в лимит шагов до `finish`: 25 из 47 ответов модели обрезаны
`max_tokens=2000` (GLM-5.3-Flash тратит лимит на скрытое рассуждение и не успевает вызвать инструмент). Исправлено:
`ChatModels.agent()` по умолчанию 16000 (с 22.10 — 64000). Разбор прогона —
[`../../../research-agent-first-run.md`](../../../research-agent-first-run.md). После правок агент живьём ещё не запускался.

**Трейс в Langfuse.** Один прогон = один трейс `research_agent <id>` (`common.llm.trace_config`): внутри все вызовы
модели, инструменты данных, инструменты памяти (включая `finish`) и подграф проверки `tool_loop:report_verdict`.
Сессия — `agent-<дата>-<время>` (`RUN_ID`).

**Второй прогон (16k, ~16 ₽).** Обрезки нет, но 33 из 40 шагов — один и тот же `table_query`: GLM передаёт
списки и словари (`filters`, `group_by`, `agg`) JSON-строкой, pydantic их отклонял, модель повторяла вызов.
Исправлено: `common.llm.json_args` декодирует такие строки для полей, которые не принимают строку (инструменты
данных, инструменты памяти, финал `ToolLoop`). Повтор вызова, уже вернувшего ошибку, агент не выполняет, а
отвечает подсказкой (`prompts/repeated_error.md`).

**Третий прогон (~16 ₽) — первый успешный:** `finish` за 17 шагов, 8 гипотез (5 supported), 9 новых фактов,
1 трейс в Langfuse. Один новый факт частично выдуман (карточка U_106783 приписана контрагенту), два повторяют
известные — нужна самопроверка фактов перед `finish`. Разбор — `research-agent-first-run.md`.

## Устройство
```
START → research → act ─┬─ summary / лимит шагов ───────────→ END
          ↑             ├─ конец подзадачи / бюджет → compact ─┐
          └─────────────┴──────────────────────────────────────┘
```
| Файл | Что |
|---|---|
| `agent.py` | `ResearchAgent`: граф `StateGraph(ResearchState)` с чекпойнтером `InMemorySaver`. Узлы `research` (модель с инструментами), `act` (исполнение вызовов), `compact` (сжатие) |
| `memory.py` | `Memory`: новые факты (из `finish`), гипотезы со статусами, архив сырых наблюдений `obsN`; хранится в состоянии графа. Pydantic-схемы инструментов памяти (`propose_hypothesis`, `verify_hypothesis`, `recall_observation`, `finish`) и `Verdict` |
| `data_tools.py` | `CompanyDataTools`: 7 инструментов только для чтения (`company_card`, `counterparties`, `payments_between`, `group_members`, `person_links`, `peer_stats`, `table_query` с фильтрами по белому списку, без eval и shell) |
| `prompts/` | Все тексты для модели: системный промпт, задача, проверка гипотезы, сжатие, напоминания |
| `test_agent.py` | Офлайн-тест: 9 скриптованных ответов проходят весь граф, включая отказ в `finish`, подграф проверки и сжатие; проверяет, что прогон — одно дерево трейса и `finish` виден в нём |

**Проверка гипотез (подграф, Chain-of-Verification).** `verify_hypothesis` запускает `common/llm/tool_loop.ToolLoop`
в чистом контексте: 2–4 вопроса, ответ на которые может гипотезу **опровергнуть** → ответы через инструменты →
`report_verdict` (supported / plausible / weak / refuted). Наблюдения подграфа попадают в тот же архив `obsN`.

**Сжатие контекста.** Триггер — конец подзадачи (после вердикта, как в SelfCompact) или бюджет символов. Сжимается
только рабочий транскрипт; задача и память вставляются дословно; сырые наблюдения перечитываются через `recall_observation(obsN)`.

**Самопроверка.** `finish` отклоняется, пока есть непроверенные (open) гипотезы.

## Учтённые подходы
ReAct; Chain-of-Verification с целью «опровергнуть»; Reflexion-самопроверка перед `finish`; память в стиле MemGPT / Letta
(постоянный блок + архив по id); сжатие на границе подзадачи (SelfCompact) с возможностью восстановить детали;
Plan-and-Execute — план просим в первом ответе, без отдельного планировщика.
