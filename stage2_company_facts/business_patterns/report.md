# Факт-паттерны компаний и архетипы бизнеса: результаты исследования (20.10.2026)

**Цель.** Найти типы компаний с двух сторон и честно сопоставить их:
1. **Архетипы** — из экономической теории и российской практики;
2. **Факт-паттерны** — только из данных кейса (таблицы, граф платежей), без догадок о бизнес-модели.

Это опора для оценки этапа 2: «правда по построению» для гипотез о бизнес-модели берётся у компаний,
чьи факты однозначно совпадают с паттерном.

Код: [`features.py`](features.py) (90 признаков на компанию), [`patterns.py`](patterns.py) (флаги, NMF-поиск, каталог).

## 1. Главное ограничение данных — видимость платежей

**Видимость платежей определяется статусом клиента банка, а не бизнесом компании.**

| Статус | Есть исходящие | Есть входящие | Медиана «входящие / выручка» |
|---|---|---|---|
| CLIENT (42 тыс.) | 84% | 79% | 0,099 |
| CLOSE_CLIENT (7 тыс.) | 66% | 57% | 0,003 |
| PROSPECT (37 тыс.) | 50% | 35% | 0 |

- У не-клиентов виден только тот поток, где контрагент сам клиент Альфы. Даже у клиентов видно около 10% оборота: у компаний несколько банков.
- **Следствие:** абсолютные объёмы платежей для паттернов использовать нельзя. Используется только **форма** видимого потока: доли, концентрация, отрасли контрагентов, баланс входа и выхода.
- Анализ сделан на **16 540 «наблюдаемых» компаниях**: клиенты, ≥10 контрагентов (≥3 в каждую сторону), видимый поток ≥10% выручки.
- Из 115 крупных компаний (≥15 млрд) наблюдаемы только **57**. Для остальных 58 паттерны по платежам **недоступны в принципе**.

Остальные свойства данных, которые влияют на выводы:
- **Выручка** — годовая и, вероятно, за прошлый год. Поэтому у молодых компаний обороты ≫ выручки — артефакт сроков, а не бизнес-модель (паттерн FP06).
- **ФТС** — страны без направления. В поле максимум 3 страны: похоже на обрезку.
- **Численность**: заполнена только градация ФНС из 4 корзин; «Менее 15» у 69% компаний.
- **ОКВЭД** контрагента известен только для 27–45% суммы платежей (`in_known` / `out_known`).

## 3. Сторона 2: факт-паттерны из данных

### Метод
1. **44 факт-флага** — пороги на одном признаке: «≥80% входящих от одного плательщика», «≥50% исходящих своей группе»,
   «плательщиков больше, чем у 90% отрасли» и т.п. Квантили берутся внутри раздела ОКВЭД. Каждый флаг — проверяемый факт о видимых данных.
2. **Кластеризация HDBSCAN по всем признакам сразу не сработала.** Она дала один большой «типичный» ком (59% — шум)
   и мелкие кластеры по масштабу, бизнес-модели не разделялись. Это ожидаемо: бизнес-модели — не плотные сгустки
   в общем пространстве признаков.
3. **NMF на матрице «компания × флаг»** — подход ролей RolX, флаги взвешены по редкости. Устойчивость компонент проверена
   на 10 бутстреп-выборках: совпадение по косинусу после сопоставления. Прогоны: опт (46), стройка (41–43), все наблюдаемые.
   В опте устойчивость большинства компонент 0,9–1,0. При большом числе компонент NMF вырождается в одиночные флаги.
4. **Перекрёстная проверка совместной встречаемостью**: насколько чаще случайного флаги встречаются вместе (lift).
5. **Каталог из 20 паттернов** — конъюнкции 2–3 флагов, считанные с устойчивых компонент.

**Как читать метрики в таблице:**

| Метрика | Что показывает |
|---|---|
| lift | во сколько раз чаще флаги встречаются вместе, чем при независимости |
| **cohesion** | насколько участники паттерна похожи **по остальным флагам**, не входящим в его определение. 1,0 — не больше случайных пар; ≥1,5 — настоящая группа |
| flow_vs_peers | медиана видимого потока / выручку у участников относительно аналогов по разделу. ≪1 — риск, что паттерн создан частичной видимостью |
| обогащение | доля раздела ОКВЭД среди участников / доля среди всех наблюдаемых |

## 5. Честные выводы

1. **Из 20 паттернов только 2 однозначно соответствуют архетипу:** техзаказчик девелоперской группы (FP23, n=25) и топливный трейдер (FP07 в 46.71, n=26).
   - Ещё 6 паттернов совместимы с семьёй архетипов («зависимый поставщик», «внутригрупповой узел», «дистрибьютор для розницы», «поставщик госзаказа»).
   - Остальные — отраслевые признаки, масштаб, структура группы или артефакты данных.
2. **Многие паттерны заново открывают ОКВЭД** (транспорт → 52, недвижимость → 68, стройка → 41). Это проверка метода, а не новое знание.
   - Ценны паттерны, которые объединяют компании **разных** ОКВЭД или разделяют компании внутри одного класса: FP10, FP02, FP01, FP07.
3. **Настоящие группы** (cohesion ≥2: участники похожи не только по определению) — FP10, FP11, FP22, FP23, FP24. Паттерны с cohesion ≈1 (FP03, FP05, FP12, FP20) — описательные срезы, а не кластеры.
4. **Покрытие крупных компаний плохое:**
   - паттерны по платежам доступны для 57 из 115 крупных;
   - из этих 57 у 25 нет ни одного паттерна, кроме структурного FP12;
   - чаще всего у крупных — FP04, то есть просто масштаб.

   Для целевого сегмента ТЗ основной источник фактов — карточка и группа, а не граф платежей.
5. **Сверка с golden set этапа 2** (ручной разбор, независимый от этого исследования):
   - из 7 наблюдаемых компаний у 2 паттерн согласуется с ручным выводом: U_44767 SPV → FP01, U_76122 кэптивный субподрядчик → FP02 + FP27;
   - у остальных паттерны неинформативны или их нет;
   - 2 компании (U_68622, U_257637) не наблюдаемы.
6. **Паттерны «сквозной поток», «молодая + обороты ≫ выручки», «мало людей + большие обороты» совпадают с признаками транзитных операций** из методических рекомендаций Банка России. Мы **не размечаем** компании таким образом и не показываем это клиенту: это факт-паттерны о видимых данных, а не доказательство. У них есть законные объяснения — SPV, агент, трейдер, отчётность за прошлый год.
7. **Не проверено:**
   - чувствительность к порогам флагов: пороги заданы вручную, устойчивость проверялась только для NMF-компонент;
   - стабильность во времени: в данных нет дат.

## 6. Что это даёт этапу 2 и его оценке
- **«Правда по построению» для гипотез агента.** У компаний из FP23 и FP07 (46.71), а также у ручных случаев FP01 + группа (SPV) архетип однозначен.
  - Метрика: находит ли агент эти архетипы на реальных компаниях, не зная паттерна.
  - Это и есть набор для оценки гипотез, который заменяет синтетику на первом шаге.
- **Новые факты в профиль.** Паттерны с cohesion ≥2 стоит выдавать агенту как готовые факты: «внутригрупповой узел», «кэптивный поставщик группы». Формулировки — только фактические, из колонки «Факты».
- **Следующие шаги:**
  1. проверка чувствительности к порогам;
  2. отдельный признак «закупки у производителя своей группы» для A2;
  3. ручная проверка 10 случайных участников FP23 / FP07 / FP10: подтверждает ли полный разбор архетип;
  4. перенос на 41.10 / 71.12 и 46.71 как первые отрасли с однозначными архетипами.
