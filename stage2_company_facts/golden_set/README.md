# Golden set этапа 2: факты и гипотезы о 9 компаниях

**Важно: это complexity-set, не целевой сегмент кейса.** `companies.json` выбирался полосами ранга выручки
*внутри* ОКВЭД (лидер/топ-20%/топ-70%) ради разнообразия бизнес-моделей для теста извлечения фактов — порог
кейса «выручка свыше 15 млрд ₽» (`case-notes.md`) в этой выборке не участвовал, и ни одна из 9 компаний ему
не удовлетворяет (максимум 11,78 млрд). Для демо, докстрингов и e2e — см. `companies_large.json` ниже, а не
эти 9: только там компании являются целевым пользователем кейса.

| Файл | Что |
|---|---|
| `company_facts_golden.json` | **Golden set.** По каждой компании: `facts` (проверенные, с `keys` — подстроками для автоподсчёта покрытия) и `hypotheses` (текст, за, против, тест на опровержение, статус supported / plausible / weak) |
| `companies.json` | Выборка: 41.20 / 62.01 / 56.10 × лидер (топ-3) / ~топ-20% / ~топ-70%; в полосе берётся компания с наибольшим числом платёжных связей |
| `industry_context.json` | Отраслевой контекст трёх ОКВЭД (тренды, технологии, id новостей). Справочник, не golden set |
| `pick_companies.py` | Выбор компаний → `companies.json` |
| `explore.py`, `probe.py` | Как собирался golden set: сырой разбор аналитика и прицельные проверки, которые пытаются опровергнуть гипотезы |
| `coverage.py` | Полнота детерминированного скрипта: факт покрыт, если все его `keys` встречаются в фактах компании (содержание, не форма) |

## `companies_large.json` — 10 компаний, целевой сегмент кейса (≥15 млрд ₽)

10 разных ОКВЭД (торговля / производство / стройка / транспорт / лизинг / IT — не только опт), по 1 компании,
у каждой **своя** выручка ≥15 млрд. Выбор нарочно не топ-1 везде: для ОКВЭД, где уже есть ручной разбор лидера
в `insight-examples.md` / `company-first-trace.md` (зерно, топливо, фарма, строительство), взята компания из
нижней части диапазона — диверсификация от «чуть выше порога» (15,56–15,99 млрд) до «флагман отрасли» (32,25 млрд).
Там, где ≥15 млрд в ОКВЭД только одна компания (27.12, 49.41.2, 64.91.2, 62.01), взята она — это и top1, и min
одновременно. `pick_companies_large.py` → `companies_large.json`; факты — `deterministic_facts/facts.py --ids
<10 id> --out data/companies/facts_large.jsonl` (median 76, max 98 фактов на компанию; флаг «крупный бизнес по
критерию кейса» срабатывает на всех 10 — на `companies.json` он не срабатывал ни разу).

**Как собран**: разбор каждой таблицы (карточка, группа, физлица, платежи в обе стороны, второй уровень цепочки,
контрагенты вне базы через их платёжный граф, сравнение с аналогами). Гипотезы оставлены конкурирующими, если
реалистичны обе. Каждая проверялась запросом, который мог её опровергнуть (`probe.py`).

**Результат**: скрипт покрывает 65/65 фактов. Это оптимистично: факты писались после просмотра выхода скрипта v1.
Честная проверка — новые компании, по которым golden set составлен до запуска скрипта.

Самые сильные находки ручного разбора:
- **U_44767** — SPV-застройщик: выручка ≈0 при обороте 1,2 млрд, деньги инвестора идут генподрядчику и в стройконтроль.
- **U_57162** — платёжный центр туристической группы под ОКВЭД ресторана.
- **U_68622** — поставщик или франчайзер пекарен и кафе СПб; кафе U_220924 из той же выборки — его покупатель.
- **U_174807** — ПО для общепита.
- **U_49717** — SaaS для малого и среднего бизнеса.
- **U_76122** — кэптивный субподрядчик московского генподрядчика.
