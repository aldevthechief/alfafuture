# Гибридный поиск и индекс фактов

RelatedNews.search объединяет три канала: TF-IDF по заголовкам и фрагментам, существующие векторы FRIDA и TF-IDF по извлечённым сведениям. Общий common/fusion.py использует RRF; он также подключён к генераторам stage 3. По каждому каналу отбирается короткий список, объединение ограничивается 40 кандидатами (или k, если k больше). Дубликаты объединяются по строке исходной статьи.

После объединения SemanticRanker совместно оценивает запрос и текст каждого кандидата через CrossEncoder. По умолчанию используется BAAI/bge-reranker-v2-m3, CPU, batch 8, максимум 512 токенов на пару. Найденные подтверждающие фрагменты идут перед началом статьи. Модель загружается лениво при первом непустом поиске; первый запуск может скачать веса. RERANKER_MODEL и RERANKER_DEVICE задают модель и устройство. NEWS_SEARCH_DENSE=0 и NEWS_SEARCH_RERANK=0 отключают соответствующие этапы. Ошибка загрузки или выполнения модели вызывает предупреждение и сохраняет выдачу остальных каналов; details находятся в DataFrame.attrs['search_diagnostics'].

similarity теперь содержит RRF, а не косинусную близость. retrieval_score сохраняется после переранжирования, rerank_score содержит оценку cross-encoder. search_channels/channel_scores объясняют первичный отбор, matched_facts и matched_fragments возвращают сведения и исходные цитаты.

## Подготовка фактов

ConsequenceExtractor извлекает для каждого подтверждённого факта participants, industries, countries, commodities и change. Цитата проверяется по исходному тексту. Сведения индексируются с ID новости, отпечатком статьи и версией схемы/промпта. Смысловую корректность полей определяет извлекатель; код проверяет происхождение цитаты.

Из корня проекта, после настройки LLM_API_KEY:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m stage1_news_pool.enrich_facts --limit 20
.\.venv\Scripts\python.exe -X utf8 -m stage1_news_pool.updater --interval 900 --days 7 --enrich-facts --fact-limit 20
```

Первая команда обрабатывает существующий корпус. Вторая пополняет новости и обогащает их в отдельном процессе. Извлечение фактов требует LLM; без --enrich-facts сборщик работает как раньше. --limit/--fact-limit ограничивает число попыток для новых или изменённых статей, включая неудачные.

SQLite хранится в ALFA_DATA/news/facts.sqlite3 и исключён из Git. Каждая завершённая статья сохраняется отдельной транзакцией. Повторный запуск пропускает готовые результаты, повторяет ошибки и продолжает оставшийся объём. Изменение текста или версии извлечения делает прежние сведения недоступными в текущем поиске; исторические версии остаются в базе. Удалённые из корпуса статьи не возвращаются. Статьи без извлечённых фактов также считаются обработанными, если извлечение прошло успешно. Обновлятор продолжает очередь фактов даже при отсутствии новых загрузок. Поисковый запрос не вызывает LLM; без подготовленной базы канал фактов пуст.

## Проверка

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest test_hybrid_news_search test_news_updates test_merge_regressions test_news_corpus test_pipeline_failures
```

Тесты используют синтетические тексты и модели: проверяют объединение каналов, порядок и ограничение пар cross-encoder, цитаты, обновление изменённых статей, восстановление после ошибок и повторный запуск. Они не измеряют качество настоящей модели на golden set.

API cross-encoder: https://www.sbert.net/docs/cross_encoder/usage/usage.html
Модель: https://huggingface.co/BAAI/bge-reranker-v2-m3

Обновление корпуса во время анализа: запуск закрепляет один снимок; последующие запросы видят новое состояние. Подробности условной загрузки и инкрементального кеша FRIDA — в [UPDATER.md](../stage1_news_pool/UPDATER.md).
