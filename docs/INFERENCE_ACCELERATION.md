# Выборочный перенос ускорений из maxon-into-demo

Источник: `cf00ecf5f1f0f2ca16c5b8c530c1b76e0cd3fab0`. Полный merge ветки не выполнялся.

Перенесено:

- Async-вызовы relevance, consequences, judge/tool loop и writer; один event loop на новостную ветку анализа.
- Синхронные точки входа сохранены, включая компоненты, которые предоставляют только sync-методы.
- Ключ кеша не зависит от ID, usage и response metadata прошлых AI-сообщений. Содержимое,
  вызовы инструментов, их результаты и параметры модели остаются частью идентичности запроса.
  Старые ключи также читаются; перезапись или очистка существующих кешей не требуется.
- Вычисление consequences для одного ключа защищено от дублирования между sync/async задачами.
- Cross-encoder использует тот же lock и механизм однократной загрузки, что и остальные локальные энкодеры.
- Параллелизм по умолчанию: API `4 → 16`, CLI `8 → 16`. Прямой Python-вызов сохраняет прежний default.

Сохранено:

- `candidates=30`, `judge=5`, прежние веса и алгоритм отбора, включённый по умолчанию reranker.
- Старая логика writer: напоминания, до двух исправлений, проверка после каждого исправления;
  ошибка checker не превращается в успешную публикацию.
- Персонализация, аудит, снимки источников и форматы результатов.
- Фронтенд, экран входа, флаги сборки, API-маршруты и их модели; единственное изменение
  публичной схемы — default существующего поля `workers` с 4 до 16 (границы 1–16 прежние).

Не перенесены UI Максона, автоматическое LLM-сжатие, дедуп-гейт, изменение reasoning,
ослабление проверок writer, отключение reranker и новые публичные туннели.

Проверки: 140 офлайн-тестов в Docker. Отдельно проверены 16 одновременных задач в одном event loop,
лимит пяти новостей для judge, повторный кеш на всех шагах, промах при изменении источников,
однократная загрузка модели, сохранение итоговых отказов checker и sync-совместимость.
Схемы шести публичных моделей сопоставлены с HEAD; отличие только в default `workers`.
Реальный LLM-прогон и измерение ускорения на платной модели не выполнялись.
