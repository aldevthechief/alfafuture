01

С чего начнём?

Выберите сценарий. Инструкция подстроит команды запуска и список того, что понадобится.

Рекомендуемый путь: сначала проверьте готовый кабинет, затем переключитесь на полный режим. В Docker PDF не обрабатываются автоматически при старте; подготовку аналитики запускают отдельно.
02

Всё необходимое — под рукой.

Для Docker-сценария Python и Node.js на вашем компьютере не нужны: зависимости устанавливаются внутри образов.

Ваш чек-лист

Отметки — ваш личный чек-лист, а не автоматическая проверка компьютера. Если браузер разрешает локальное хранение, они сохраняются на этом устройстве.

ПРОВЕРИТЬ DOCKER
docker --version
docker compose version

Обе команды должны показать версии. Интернет нужен для первой сборки; в полном режиме — также для LLM API и загрузки отсутствующих весов. GPU не требуется: Docker настроен на CPU.

2

Подготовьте файл настроек

Команда ниже создаёт файл, если его ещё нет. Существующее содержимое сохраняется.

POWERSHELL · ИЗ КОРНЯ ПРОЕКТА
if (!(Test-Path 'common/llm/.env')) {
    New-Item -ItemType File -Path 'common/llm/.env' | Out-Null
}
Для готовых карточек ключ не нужен. Пустой common/llm/.env нужен только потому, что этот файл указан в Docker Compose как bind mount.

Откройте common/llm/.env в текстовом редакторе и добавьте строку ниже, заменив значение на ключ команды. Файл должен называться именно .env, без расширения .txt.

СОДЕРЖИМОЕ common/llm/.env · НЕ КОМАНДА
LLM_API_KEY=your_team_key

Секрет остаётся на серверной стороне. Не добавляйте его в HTML-инструкцию, frontend или публичный репозиторий. Адрес прокси и модели задаются в common/config.py; при необходимости поддерживается LLM_BASE_URL.

Для анализа PDF нужны подготовленные материалы. Полная обработка сканов, графиков и таблиц запускается явно и может обращаться к платным моделям. Для первого прогона только по новостям используйте CLI-команду в разделе диагностики.
3

Поднимите приложение

Сборка общая для четырёх сервисов: интерфейса, основного API, API обсуждений и Redis. Дождитесь окончания команды; время зависит от сети и компьютера.

POWERSHELL · ИЗ КОРНЯ ПРОЕКТА
$env:CABINET_MODE='server'
docker compose up -d --build

Флаг задаётся явно: без него Compose по умолчанию включает full. После изменения режима повторите этот блок, чтобы фронтенд и API работали согласованно. Порт интерфейса — 5173; backend — 18000; обсуждения — 18001.

4

Проверьте, что сервисы отвечают

В списке должны быть redis, backend, feedback-api и frontend. Вспомогательный pipeline постоянно работать не должен.

СТАТУС КОНТЕЙНЕРОВ
docker compose ps
ПРОВЕРКА ОБОИХ API
Invoke-RestMethod http://localhost:18000/health
Invoke-RestMethod http://localhost:18001/health

Ожидается status: ok. Это подтверждает доступность API; корректность ключа и готовность моделей проверяются при новом анализе. Не вводите ключи в эту страницу — она только показывает инструкции.

Проверьте обоснование

07

Что-то пошло не так?

Откройте подходящий пункт или найдите ошибку по слову: «порт», «ключ», «PDF», «сборка».

Docker не найден или не удаётся подключиться к daemon

Проверьте установку Docker и запустите Docker Desktop. На Linux проверьте, что служба Docker работает и вашему пользователю разрешено подключаться к ней. После запуска снова выполните docker compose version и docker compose ps.

Первая сборка долгая, pip / PyTorch завершились с ошибкой

Образы скачивают тяжёлые зависимости, включая CPU-версию PyTorch. Проверьте доступ к интернету и свободное место, затем повторите docker compose up -d --build. Dockerfile сохраняет pip-загрузки в кеше BuildKit и задаёт повторы сетевых запросов. Фиксированного времени первой сборки нет.

Порт уже занят: bind / address already in use

Основной API использует 18000, обсуждения — 18001, интерфейс — 5173. Для двух API можно задать другие порты в том же терминале и пересобрать контейнеры:

POWERSHELL
$env:BACKEND_PORT='18010'
$env:FEEDBACK_PORT='18011'
docker compose up -d --build

После этого Swagger будет на 18010/18011. Прокси внутри Docker продолжит работать. Если занят 5173, измените только внешний порт frontend в docker-compose.yml, например на 5174:80, и открывайте localhost:5174. Для Vite-разработки укажите новые адреса API через VITE_BACKEND_TARGET и VITE_FEEDBACK_TARGET.

Ошибка монтирования common/llm/.env или .env оказался папкой

Compose ожидает обычный файл common/llm/.env. Создайте его до запуска контейнеров — командой из шага 2. Если по этому пути появилась папка, проверьте её содержимое и вручную замените пустую папку файлом. В Windows включите отображение расширений и убедитесь, что имя не заканчивается на .txt.

Готовые карточки есть, но анализ и чат возвращают 403

В режиме server инференс намеренно отключён. Выберите «Запустить агентов» в начале инструкции, подготовьте ключ и CSV, затем выполните обновлённую команду запуска с CABINET_MODE=full. Менять только флаг фронтенда недостаточно: режимы API и интерфейса должны совпадать.

Не найдены CSV, компания или платёжные данные

Таблицы кейса не входят в публичный репозиторий. Добавьте три файла из шага «Разложите данные» прямо в data/. ID компании должен существовать в этих таблицах. Режим server позволяет читать встроенные инсайты без таблиц; платёжная аналитика и остальные обращения к исходным данным требуют CSV.

LLM: неверный ключ, 401 / 429, закончилась квота

Проверьте LLM_API_KEY в common/llm/.env, доступность прокси организаторов и квоту команды. Ключ Langfuse не даёт доступ к моделям. Посмотрите логи backend и feedback-api; не публикуйте их целиком, если они содержат данные кейса. HTTP 429 может означать как лимит провайдера, так и переполненную очередь API — причину покажет тело ответа.

Нет весов / векторов, анализ долго начинает поиск

Поиск может загружать локальные энкодеры и строить отсутствующие векторы; каталог data/retrieval_v2 не хранится в Git. Для первого небольшого прогона используйте lexical и только новости. Нужны CSV и LLM_API_KEY; контейнер pipeline соберётся при первом вызове:

CLI · ТОЛЬКО НОВОСТИ · 1 КАНДИДАТ ДЛЯ JUDGE
docker compose run --rm pipeline python -X utf8 pipeline.py U_68622 --role ceo --source news --candidates 8 --judge 1 --engine judge --retrieval lexical

Компания U_68622 должна быть в ваших CSV. --judge 1 ограничивает глубокий разбор одной новостью и не гарантирует готовый инсайт. Результат сохраняется в data/insights/U_68622_ceo.json; повторный прогон заменяет этот файл. CLI-команда сохраняет результат отдельно от очереди API и сама не создаёт новый кабинет.

Как прогреть Redis сохранёнными LLM-ответами?

В репозитории есть сжатый кеш data/llm_cache/llm.jsonl.gz. После запуска Redis можно импортировать его:

НЕОБЯЗАТЕЛЬНЫЙ ПРОГРЕВ
docker compose run --rm pipeline python -X utf8 scripts_seed_redis.py

Совпавшие запросы используют кеш; новые запросы, изменённый контекст и чат всё ещё могут расходовать квоту. Это не замена ключу для полноценного режима.

Как подготовить PDF, графики и таблицы для агентов?

Положите отчёты в data/analytics/. Полная подготовка ниже запускается явно, использует vision/LLM API и затем выполняет анализ. Подготовка общая для PDF, а --candidates ограничивает новости:

CLI · ПЛАТНАЯ ПОДГОТОВКА МАТЕРИАЛОВ
docker compose run --rm pipeline python -X utf8 pipeline.py U_68622 --role ceo --candidates 8 --judge 1 --engine judge --retrieval lexical --bank-prepare --ocr-budget 15 --charts-budget 8 --tables-budget 7 --digest-budget 3

Бюджеты заданы в рублях для этапов подготовки; генерация инсайтов оплачивается отдельно. Если бюджет закончится, подготовка может быть частичной. Этот сценарий запускайте после успешной проверки обычного анализа.

Сервисы запущены, но страница пустая или API недоступен

Проверьте обе ссылки /health из шага 4 и логи ниже. Открывать нужно http://localhost:5173, а не HTML интерфейса из папки frontend. В Docker запросы проксирует nginx. После исправления настроек повторите запуск с --build и обновите страницу.

ЛОГИ · CTRL+C ЗАВЕРШАЕТ ПРОСМОТР
docker compose logs --tail=100 backend feedback-api frontend

Совпадений нет. Попробуйте «Docker», «ключ», «порт» или «данные».

Готово для статического хостинга

Эту инструкцию можно открыть где угодно.

Дважды нажмите на docs/index.html — страница работает локально. Для другого хостинга достаточно index.html; файл .nojekyll пригодится для GitHub Pages. CSS, схемы и JavaScript уже внутри.

  1. Добавьте docs/index.html и docs/.nojekyll в ветку репозитория и отправьте её на GitHub.
  2. Откройте Settings → Pages → Build and deployment.
  3. В Source выберите Deploy from a branch, вашу ветку и папку /docs, затем Save.
  4. Дождитесь завершения публикации. GitHub покажет адрес инструкции в настройках Pages.

Для репозитория aldevthechief/alfafuture-hack стандартный адрес после публикации:
