# Модуль генерации инсайтов: состояние и подключение бэкенда

Дата: 23.10.2026. Ветка: `integration/maxon-kirill-vovchik`.

## Что уже работает

- **Профиль компании:** загрузка из `data/companies/profiles.jsonl`, сборка из таблиц при отсутствии записи. Пояснения о чувствительности передаются модели отдельно от доказательств; повторы сокращаются кодом. Кеш профилей обновляется при изменении файла.
- **Поиск новостей:** retrieval v2/v3, объединение кандидатов и отбор событий под компанию и роль.
- **Judge:** проверяет связь новости с компанией, запрашивает дополнительные новости, факты и банковскую аналитику. Прочитанные банковские материалы передаются writer с источниками, датами и атрибуцией.
- **Loop:** альтернативный режим с расчётами последствий, объяснением уровня влияния и запросами дополнительных данных.
- **Расчёты Python:** доля выручки в группе, сравнение показателей, сценарий применения прогноза к выручке, перевод единиц. Уточнён подбор периода, типа «факт/прогноз» и валюты; неоднозначный запрос получает объяснение отказа.
- **Аналитика Банка:** поиск по подготовленным фрагментам PDF, работа с таблицами и графиками; отдельный агент умеет выпускать инсайты из отчётов без новости.
- **Карточка:** writer → самопроверка → аудит источников. Есть факты, выводы, риски, возможности, действия, гипотезы и позиция Банка. Штатный CLI сохраняет контракт v2.

## Быстрое подключение через CLI

Запускать из корня репозитория в окружении с установленными `requirements.txt`, данными и настройками API из `common/llm/.env` либо переменных окружения.

```powershell
python -X utf8 pipeline.py U_106783 --role cfo --engine judge --source news --retrieval v3 --candidates 8 --judge 4 --workers 4
```

Режимы источников:

| Параметр | Что запускается |
|---|---|
| `--source news` | Новостной сценарий выбранного движка |
| `--source analytics` | Отдельный агент по отчётам Банка |
| `--source both` | Оба сценария с объединением результатов; значение по умолчанию |

`--engine loop` переключает новостной движок. `--workers 4` задаёт параллелизм judge. Для обычного запуска на подготовленных данных флаги OCR не нужны.

## Как связать с HTTP-бэкендом

HTTP-обвязку требуется реализовать вокруг существующего модуля. Предлагаемый контракт:

1. `POST /insight-jobs`: принять `company_id`, `role`, `engine`, `source`; создать фоновое задание и вернуть `job_id`.
2. Worker запускает CLI списком аргументов, фиксирует время, код завершения и журнал. Генерация длительная, поэтому выполнять её вне HTTP-запроса.
3. `GET /insight-jobs/{job_id}`: вернуть состояние `queued/running/completed/failed` и доступный результат.

CLI записывает **список результатов** в:

```text
data/insights/<company_id>_<role>.json
```

Для ленты выбирать элементы с `status == "ready"` и полем `insight`; `draft`, `review`, `audit` и ошибки сохранять для диагностики. Отклонение новости judge может быть записано через `decision.is_insight == false` без отдельного `status`.

В карточке использовать `title`, `what_happened`, `why_it_matters`, `risks`, `opportunities`, `actions`, `bank_view`, `hypotheses`, `impact`, `confidence`, `origin`, `trigger`. Сохранять ID источников и признаки `unconfirmed`, чтобы интерфейс мог показывать происхождение утверждений.

Файл одной компании и роли перезаписывается: worker должен сохранить его копию под `job_id` перед следующим запуском и исключить одновременные задания для одной пары. Для проверки ссылок на новости доступны `common.news_corpus.load_results()` и сохранённые снимки корпуса.

При интеграции через Python `InsightPipeline.run()` возвращает результаты без сохранения и миграции в v2. Обвязка должна отдельно выполнить `migrate_result()` и `save_results()`. CLI уже делает это.

## Данные и кеши

- Новости и события: `data/news/`; профили: `data/companies/`; подготовленные отчёты: `data/analytics/`.
- Обычные векторные кеши новостей: `data/retrieval_v2/`; банковские векторы: `data/analytics/ocr/.emb_e5_*.npz`.
- Готовые оценки Максона `precomputed.npz` подключались явно тестовым скриптом. Штатный CLI автоматически не переключается на этот режим. Новые запросы могут потребовать локального энкодера даже при готовых векторах корпуса.
- Для длительно работающего Python-worker модели и поисковые индексы целесообразно переиспользовать; CLI подходит для первого подключения.
