# Вход в демо-кабинет

Две версии используют один экран выбора аккаунта: компания, должность, отрасль и число готовых инсайтов.
Нажатие компании в шапке кабинета или «Выйти» возвращает к выбору. Выбор сохраняется в sessionStorage
на время вкладки; режимы сборки имеют разные ключи. Это выбор демо-контекста, а не аутентификация сотрудников.

## Сборка

PowerShell, из корня репозитория. По умолчанию включена полная версия (`full`):

```powershell
docker compose up -d --build
```

Серверная версия включается явно:

```powershell
$env:CABINET_MODE='server'
docker compose up -d --build
```

В режиме `server` доступны только подготовленные кабинеты, API запрещает
новые анализы, подготовку PDF, поиск для агентов и вопросы с инференсом. Чтение карточек работает
без инициализации модели, очереди задач и таблиц кейса.

Полная версия с явным флагом (например, если ранее был задан `server`):

```powershell
$env:CABINET_MODE='full'
docker compose up -d --build
```

Появляется «Другая компания?»: поиск компании в данных кейса по ID или отрасли,
необязательное отображаемое название и должность. Быстрые роли: CEO, CFO, маркетинг;
остальные роли доступны в списке. Кнопка входа создаёт задачу `/v1/analyses` с `engine=judge`,
`source=both`, `analytics_cache_only=false`, `analytics_refresh=true`. Пользователь сразу
попадает в кабинет со статусом анализа. Выполняется существующий LangGraph-цикл,
результаты появляются после завершения. Новый анализ требует таблиц кейса, настроенных моделей
и источников; ввод имени произвольной компании не заменяет её профиль в данных.

Фронтенд отдельно, из `frontend/`: `npm run build:server` или `npm run build:full`.
Равнозначный флаг перед обычной сборкой: `VITE_CABINET_MODE=server|full`.
Для Vite dev: `npm run dev -- --mode server` либо `npm run dev -- --mode full`.
При запуске API отдельно задайте соответствующий `CABINET_MODE` в его окружении.
В Docker подготовка PDF при старте отключена (`API_PREPARE_ON_START=0`); в полной версии
её можно запустить явно через API. Вне Docker старое поведение прогрева сохраняется,
если не задать этот флаг.

## Готовые кабинеты

| Условное название | ID данных | Должность | Инсайты |
| --- | --- | --- | --- |
| Север Финанс | U_14366 | Генеральный директор | 2 новостных + 1 из аналитики Банка |
| Север Финанс | U_14366 | Финансовый директор | 5 |
| Горизонт Девелопмент | U_177581 | Генеральный директор | 5 |
| СибТопливо | U_57706 | Казначейство | 4 |

Все три карточки кабинета CEO сохранены в `backend/demo_cache/U_14366_ceo.json` из завершённого
агентского прогона: вместе с фактами, цитатами, URL статей и замороженными источниками.
Этот кабинет стоит первым в списке входа. Для каждого кабинета лента объединяет сохранённые
карточки из `backend/demo_cache`, `stage5_insight_detection/analytics_insights/cache`, локального
`data/api/analytics_cache` и завершённых API-прогонов той же компании и должности. Повторы по ID
инсайта удаляются; у карточки сохраняются собственный результат прогона и замороженные источники.
Данные другого пользователя, компании или должности не подмешиваются. Числа в таблице описывают
встроенный набор; локальные кеши и новые прогоны могут увеличить число карточек.
Не создаются фиктивные результаты для отсутствующих комбинаций компании и роли.
Названия компаний и денежные показатели банковской оболочки демонстрационные.
История операций на главном экране сохраняет прежнюю разметку и демо-данные.

`GET /v1/cabinet/accounts` отдаёт только метаданные кабинетов. Лента содержит краткие превью;
полный текст и замороженные источники запрашиваются отдельно для открытой карточки.
`GET /v1/cabinet/feed?company_id=…&role=…` отдаёт общую ленту превью. Интерфейс обновляет её
раз в пять секунд: завершённый инференс дополняет кеш, а сбой одной ветки не скрывает уже
готовые карточки другой. Чтение ленты не запускает модели. Полные источники остаются отложенными
до открытия конкретной карточки.

## Проверки

`node --test frontend/tests/*.test.js` проверяет различия экранов двух сборок,
запрет отправки анализа в серверной версии, запрос нового анализа и отложенную загрузку карточек.
`tests/unit/backend/test_cabinet.py` проверяет готовые карточки и ссылки на источники,
запрет инференса, очередь полной версии, поиск и отсутствие прогрева в серверном режиме.
