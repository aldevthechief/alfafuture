# Этап 4. Может ли новость быть интересна компании + правдоподобие

Вход — shortlist этапа 3. Выход на новость: оценка связи с компанией и ролью, экономические последствия новости,
правдоподобие события. По ним этап 5 выбирает, какие новости разбирать глубоко.

| Подход | Папка | Суть | Статус |
|---|---|---|---|
| Последствия новости | [`consequence_extraction/`](consequence_extraction/consequences.py) | `ConsequenceExtractor`: дешёвая LLM читает каждую новость **один раз** → `NewsConsequences` (economic, status факт / план / слух, кого затрагивает: подсказка ОКВЭД, регион, страна, канал, направление). Кеш на новость, общий для всех компаний. `match_consequences` сопоставляет с компанией кодом | ✍ без запуска |
| Ранкер 1: LLM + пакеты | [`batch_ranker/`](batch_ranker/ranker.py) | `BatchRanker`: одна LLM-выжимка фактов о компании (кеш) + пакет из 25 заголовков с лидами (генераторы перемешаны) → keep / drop и канал по каждой. Приоритет полноты: сомнительное и пропущенное моделью остаётся. Лид — описание из RSS или текст без повтора заголовка. Другие подходы ранкера 1 (по одной новости, cross-encoder) — в бэклоге | ✍ без запуска, офлайн-тест `test_ranker.py` |
| Оценка релевантности | [`relevance_scoring/`](relevance_scoring/relevance.py) | `RelevanceScorer`: дешёвая LLM на тройку (новость, роль, факты) → `Relevance` (0–3, через какой факт связана, канал, направление, соответствие роли) | ✍ без запуска |
| Правдоподобие | [`plausibility/`](plausibility/events.py) | Склейка сообщений в события: косинус по основам заголовка и лида ≥0.45 и даты в пределах 3 дней (связные компоненты). Оценка 0..1: число независимых источников, доля tier 1, официальный источник, **несогласованные числа** внутри события | ✅ 8 996 новостей → 8 037 событий, 651 из нескольких сообщений, 13 с несогласованными числами. Компоненты больше 10 сообщений дробятся повышением порога (раньше «все закрытия аэропортов» склеивались в событие из 51 сообщения, теперь максимум 9) |
| Объединяющая новость | [`plausibility/event_summary.py`](plausibility/event_summary.py) | `EventSummarizer`: дешёвая LLM по заголовкам сообщений события пишет один заголовок и 2–3 предложения. Лениво: только события от 5 сообщений и только после генерации кандидатов; кеш на событие | ✍ без запуска, офлайн-тест `test_events.py` |

Промпты — в `prompts/` каждого подхода; выход LLM — pydantic-модели через `common/llm/models.structured`.

**Предложено, не реализовано:**
1. Проверка противоречий LLM-ом: утверждения из сообщений одного события (кто, что, сколько, когда) сравнить между собой.
2. `status` из последствий (факт / план / предложение / слух) как множитель правдоподобия.
3. Репутация источника по истории: как часто его «планы» потом подтверждались официально.
4. Сверка чисел новости (ставка, инфляция, курс) с прогнозами Банка.
5. Перепубликации: дата события ≠ дата публикации.

**Golden set**: пока нет. Предложение: ~100 пар новостей «одно событие или нет» → точность и полнота склейки;
подсадка ложных или устаревших новостей → доля отсеянных; разметка «интересно / нет» на shortlist для калибровки оценки.

python -X utf8 stage4_news_relevance/plausibility/events.py   # -> data/news/events.parquet
