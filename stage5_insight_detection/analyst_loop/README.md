# Агентный цикл аналитики Банка

Одно событие × одна компания × одна роль: от аналитики Банка до обоснованного инсайта или отказа с причиной.
Числа считает код, текст пишет модель: LLM вызывается не больше двух раз на событие (объяснение посчитанных
последствий и формулировка инсайта), всё остальное детерминировано и трассируется.

```
карточка события ─> подбор аналитики Банка (2) ─> возврат к пулу новостей (3) ─> последствия (5) ─> риски и возможности (6)
        ^                                                                                              │
        └──── запросы недостающих данных (4) <──── проверка оснований (7) <──── модель объясняет ───────┘
                                                          │
                                                          └─> вердикт (8): бриф -> писатель этапа 6 -> аудит ответа | отказ
```

| # | Задача | Где | Как |
|---|---|---|---|
| 1 | Парсинг аналитики Банка | [`../bank_analytics/library.py`](../bank_analytics/library.py) | Загрузчик по папке `data/analytics/`: новый или изменённый PDF (реестр по хешу) → текстовый слой или OCR (`ocr.py`, Qwen3-VL) → фрагменты `bank:<файл>:p<стр>.<n>` с отчётом, датой, страницей, заголовком, темами, числами (значение, единица, показатель, период, прогноз/факт), признаком «собственная позиция Банка» («мы ожидаем», «наш прогноз») и направлением позиции. Свежесть считается на дату проверки: fresh ≤ 60 дней, aging ≤ 365, stale > 365, unknown без даты. Дата отчёта: `reports.json` → имя файла (22072026, 11Sep, August26, 15Apr2021) → первая страница |
| 2 | Подбор аналитики под событие и профиль | [`../bank_analytics/match.py`](../bank_analytics/match.py) | 0.45 близость текста + 0.25 общие темы + 0.20 чувствительность компании к темам фрагмента + 0.10 собственная позиция Банка; устаревшие ×0.3 и всегда в конце. У каждого совпадения в журнале части оценки и причина |
| 3 | Возврат к пулу новостей и дополнение аналитики | [`enrich.py`](enrich.py) | Другие сообщения о событии и развитие темы; новости новее отчёта Банка по тому же показателю (если число другое — `newer_data`); повторный поиск по аналитике с терминами подтверждений и сильных каналов компании |
| 4 | Запросы недостающих данных в общий цикл | [`data_requests.py`](data_requests.py) | `DataRequest` поднимает код (нет позиции Банка по макроканалу, расходятся числа, нет связи с компанией) или модель (`missing`). Брокер отправляет запрос инструменту (аналитика Банка, пул новостей, факты этапа 2), не больше раза на запрос и в пределах бюджета; ответы меняют досье, цикл пересчитывает последствия. Незакрытые запросы возвращаются в результат `open_requests`, блокирующие становятся причиной отказа |
| 5 | Оценка последствий для бизнеса клиента | [`impact.py`](impact.py), [`profile.py`](profile.py) | Профиль: чувствительность к каналам по фиксированным правилам (ОКВЭД → раздел → база; продукты Банка; ФТС; платежи контрагентам по отраслям). Последствие: знак и механизм из таблицы, изменение показателя (новость минус последний факт в аналитике Банка, иначе чувствительность на 1 п.п.), количественная оценка от выручки. Допущения (доля долга в выручке, доля статьи затрат) — `Fact(kind='hypothesis')` |
| 6 | Риски и возможности с учётом позиции Банка | [`risks.py`](risks.py) | Знак → риск / возможность / наблюдать. Позиция Банка по теме (свежие фрагменты, сначала собственный взгляд): то же направление → `bank_supported`, блок «Позиция Банка»; противоположное или пауза → `bank_disagrees`; нет аналитики → вывод AI, «не официальная позиция Банка». Роли по темам |
| 7 | Достаточность и непротиворечивость оснований | [`grounds.py`](grounds.py) | Фатально: нет источника или даты, правдоподобие < 0.3, нет связи с фактом о компании. Предупреждения: нет позиции Банка, только устаревшая аналитика, Банк ждёт иного, новость новее аналитики, источники расходятся в числах, high на одном источнике (понижается до mid) |
| 8 | Передача вывода на формулировку или отказ | [`verdict.py`](verdict.py), [`audit.py`](audit.py) | Отказ: фатальные проблемы, открытый блокирующий запрос, все последствия low при важности ≤ 2. Иначе `InsightBrief` (разрешённые ссылки, факты с формулами, последствия с уровнями, риски по основаниям, гипотезы, влияние) → `InsightWriter` этапа 6 → аудит ответа кодом |

Уровни влияния (`impact.IMPACT_CRITERIA`): score = чувствительность (0–1) × важность события (1–5)/5 × подтверждение
(1.0 — свежая аналитика Банка или ≥ 2 источника, иначе 0.7). high: score ≥ 0.55 и количественная оценка ≥ 1% выручки;
mid: score ≥ 0.3; иначе low. Без числа уровень не выше mid.

## Приёмы из FinRobot (идеи, свой код)

| Приём | Где |
|---|---|
| Числа считает код, текст пишет LLM; тест падает, если в слое расчётов появится импорт LLM | весь слой расчётов; проверка в `test_analyst_loop.py` |
| Модель возвращает только оценки новостей (категория, тональность, важность 1–5, роли); заголовок, дата, ссылка — из исходника по номеру; пропуски переспрашиваются до 3 раз, первая оценка не перезаписывается, неоценённое выкидывается с записью в журнал; дата без разбора = None | [`../../stage4_news_relevance/news_classifier/`](../../stage4_news_relevance/news_classifier/classifier.py) |
| Защита от инъекций: чистка заголовков и текстов, обёртка `<untrusted_item>`, одна функция вывода в промпт | [`../../common/safety.py`](../../common/safety.py) |
| Дедупликация из разных источников: точные дубли по url и заголовку, перепечатки по косинусу основ в окне 72 ч, все источники сохраняются | [`../../common/dedup.py`](../../common/dedup.py) |
| Проверки после ответа модели: ссылка есть и существует, вывод без цифры, позиция Банка только со ссылкой на свежую аналитику (иначе переносится в вывод AI), продукт только под риск | [`audit.py`](audit.py) |
| Журнал шагов в JSONL (0600, ключи маскируются) и карточка с источником по наведению, отдельными блоками «Позиция Банка» / «Вывод AI» / «Гипотезы» | [`../../common/trace.py`](../../common/trace.py), [`../../stage6_insight_generation/insight_card/render.py`](../../stage6_insight_generation/insight_card/render.py) |

Код FinRobot (Apache 2.0) не копировался, перенесены только идеи, поэтому в THIRD_PARTY_NOTICES он не нужен.

## Форматы входа

- **PDF аналитики** кладутся в `data/analytics/` (в .gitignore). Текст страниц берётся из текстового слоя или из OCR
  `data/analytics/ocr/<имя файла без .pdf>.jsonl`: по строке на страницу `{"key": "<номер страницы с 1>", "value": "<текст>"}`
  (так пишет `ocr.py`). Абзацы разделяются пустой строкой; жирный «лид:» в начале абзаца становится заголовком.
- **Метаданные** — `../bank_analytics/reports.json` (`file`, `title`, `date`); для новых файлов дата берётся из имени или первой страницы.
- **Результат** — `data/analytics/fragments.jsonl` (поля `library.Fragment`) и `data/analytics/registry.json` (хеши файлов).
- **Синтетика для тестов** — [`synthetic/`](synthetic): `bank_pages.json` (файл → тексты страниц), `news.json` (строки пула
  новостей как у этапа 1), `company.json` (поля `CompanyProfile`). Числа выдуманы.

## Запуск

```bash
python -X utf8 stage5_insight_detection/analyst_loop/test_analyst_loop.py      # офлайн, без ключа и данных кейса
CARD_OUT=card.html python -X utf8 stage5_insight_detection/analyst_loop/test_analyst_loop.py   # + демо-карточка
python -X utf8 stage5_insight_detection/bank_analytics/library.py [--ocr]      # разобрать папку аналитики
python -X utf8 stage5_insight_detection/bank_analytics/library.py --search "ключевая ставка прогноз"
python -X utf8 stage5_insight_detection/analyst_loop/loop.py U_68622 5711 --role cfo   # одна новость, нужен LLM_API_KEY
python -X utf8 pipeline.py U_68622 --role cfo --engine loop                     # этапы 2–6 через цикл; карточки в data/insights/cards/
```
