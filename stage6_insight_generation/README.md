# Этап 6. Формируем инсайт и вывод под роль пользователя

**Вход**: положительное решение этапа 5 (`InsightDecision`) + материалы: новость и дополнения к ней, факты о компании,
абзацы аналитики Банка. **Выход**: `Insight` — JSON для интерфейса Альфа-Бизнес.

| Подход | Папка | Суть | Статус |
|---|---|---|---|
| Писатель + проверка | [`insight_writer/`](insight_writer/writer.py) | `InsightWriter`: две цепочки LangChain. `write` → `Insight` (схема в `insight.py`), `check` → `Review` (каждое утверждение сверяется с материалами); при замечаниях одна переработка. Промпты `prompts/write.md`, `prompts/check.md` | ✍ офлайн-тест в `test_pipeline.py` |

**Формат инсайта** (ответы на вопросы ТЗ): что произошло → почему важно этой компании → риски и возможности →
действия → как оценивает Банк → на чём основан вывод. Слои разделены полями: `what_happened` (факты из новостей),
`bank_view` (только аналитика Банка), `why_it_matters` / `risks` / `opportunities` / `ai_conclusion` (выводы AI).
У каждого утверждения `sources`: `news:<id>`, `bank:<отчёт>:<стр>`, `fact:<n>`. Есть `confidence` и необязательный `bank_product`.

**Персонализация по роли** (в `prompts/write.md`): собственник — стоимость бизнеса и стратегия; CEO — рынок и операционка;
CFO — ставка, долг, ликвидность, курс, налоги; главбух — налоги, отчётность, сроки правил; казначейство — ликвидность,
размещение, валютные позиции. Действия — 1–3 шага в зоне ответственности роли со сроком или триггером.

**Финальная оценка ленты** (план) = значимость × релевантность (этап 4) × правдоподобие × соответствие роли × новизна
(о чём пользователь уже знает — ниже).

## Golden set / бенчмарк — как собрать
1. **Затравка**: 10 разобранных примеров «новость → компания → инсайт» уровня L3 (`insight-examples.md` в рабочей папке)
   и проверка их предположений по данным.
2. **Попарные сравнения**: аналитики Банка выбирают лучший из двух инсайтов на одну пару (событие, компания) →
   модель Брэдли–Терри или Elo. Это дешевле и согласованнее шкалы 1–5.
3. **LLM-судья с рубрикой ТЗ** (6 вопросов + 12 критериев: интерпретация, а не пересказ; позиция Банка отделена;
   источники; конкретность действия). Судья калибруется на людях: согласие ≥85–90%, как в FinRpt.
4. **Метки «инсайт или нет»** на стратифицированной выборке (событие × компания) из пула этапа 3, с согласием двух разметчиков.
5. **Контрфактические тесты**: подмена компании → инсайт меняется; подмена события на нерелевантное → оценка падает;
   подсадка ложной новости → её отсекает правдоподобие.
6. **Отложенные метки**: через N недель проверить, материализовалось ли последствие.
7. **Метрики**:
   - precision@5 ленты на (компания, роль);
   - доля закрытых вопросов ТЗ;
   - доля утверждений с проверяемой ссылкой;
   - доля «общих мест» (одинаковый инсайт для ≥3 компаний).
